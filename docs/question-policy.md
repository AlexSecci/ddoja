# Hands-free questioning policy — October 24, 2026

The user explicitly replaced the earlier first-encounter technology-question rule. The target is credible interview opportunities with minimal interruptions, including applications where some qualifications are missing. Truthful applicant claims remain mandatory.

Agents first use the master resume, scoped saved answers and relevant indexed source sections. They can use direct logical consequences and supported date calculations; over-18 status follows from this applicant's documented completed education and adult employment timeline, without claiming an exact birth date. General software tenure does not establish tenure with every tool. Unknown knowledge is neither a Yes nor a No.

Evaluators judge documented and transferable experience and finish approve/discard decisions with uncertainties. They do not interview the user about each JD skill, tool, minimum duration, scale or depth. A requirement's wording alone does not make it a mandatory applicant answer. Clear eligibility/scope conflicts or an absence of credible relevant experience can still justify discarding a role.

Submission agents continue that decision, inspect the actual form, skip unknown optional fields and use a fitting truthful offered alternative where available. They ask only when a truly mandatory observed form answer cannot be resolved from sources/answers, a necessary personal decision or conflicting fact prevents progress, or actual authentication/action-policy requirements need the user. They must identify the specific blocker and why sources or omission cannot resolve it. They must not silently answer No to an unknown Yes/No field.

Document writers omit unsupported claims instead of asking for extra achievements or skills to improve a draft. Existing facts and source depth constrain the document's wording.

New and resumed sessions receive the updated shared/role prompts; changed instruction hashes force the full current role instructions into an existing conversation. Evaluation reuse is already bound to prompt hashes, so older decisions are not reused under the new instructions.

Dashboard answers need only an answer. The backend records the user origin and timestamp automatically, preserving any explicitly supplied note from older clients. Approval/rejection still requires the exact explicit button choice, with optional notes; removing a mandatory explanation does not create blanket approval.

Previously queued evaluator surveys can be withdrawn by an exact, operator-reviewed list of IDs using `Store.reconsider_evaluator_questions`. This does not classify text, invent answers, decide fit or launch work. It preserves question history and saved sessions, cancels any corresponding pending shared fact, and leaves affected nonterminal evaluators interrupted for explicit resume. It refuses active workers, approvals and questions shared with a non-evaluator. Real form/authentication/action checkpoints remain pending.
