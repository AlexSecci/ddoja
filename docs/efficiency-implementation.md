## Architecture decision

Keep company discovery, one-JD evaluation and job submission. A document child runs only after an actual supported document field is observed. Keep the current 1 discovery/company, 3 evaluators/pipeline and 3 submissions/pipeline limits. The deterministic event scheduler dispatches work. A persistent host serves independent logical document tasks without merging their scope.

The [decision record](efficiency-architecture.md) compares merged roles and additional routing/review agents. None justifies extra model calls or coupling browser authority to every evaluation. Evaluator findings pass forward instead of being re-created. Writers choose and tailor verified bases; there is no scripted family classifier or universal document reused without judgment.

## Operating the revised pipeline

After a reboot, run `.\run.ps1`, open `http://127.0.0.1:8765` and refresh an existing tab for the current local session. Start a company or explicitly resume its saved run. Startup does not resume old applications. Quota resume stays manual after you confirm the reset and prefers saved sessions. An uncertain final send remains reconciliation-only.

The capacity usage panel shows actual counters/cache hits; each company's runtime panel shows sign-in, connector and worker status. `Unavailable` means unreported, not zero. Resume an interrupted/stopped gate owner to finish or reconcile its owned sign-in/recovery flow; siblings do not take over its tab or approvals.

New document workers use app-server; browser workers and existing unqualified saved sessions use CLI. A missing registry or definitively missing saved thread requires explicit recovery/replacement through the existing controls. Never switch transport to replay a potentially sent application. No API-key route is configured.

Optional `effort_calibration.py`, `saved_jd_acceptance.py` and `app_server_smoke.py` require explicit `--run-subscription`. Routine tests, historical comparisons and preservation audits make no inference calls. Future live pilots should measure successful stage completions, retries, model/tool counters, wall time and user wait separately; this rebuild deliberately made no employer submissions.
